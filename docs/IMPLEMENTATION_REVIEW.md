# TT2 역기획서 검토와 Ember Ascent 구현 현황

2026년 10월 2일 사용자 제공 `TT2_역기획서_v8.2.3_R4_202Screen_CaptureAtlas_2026-10-02.docx`를 분석하고 빈 OutRun 저장소에 Cocos Creator 프로젝트를 구성했습니다. 현재 결과는 기능 구조를 검증할 수 있는 독립 개발 빌드이며 원작의 100% 복제 완성본이 아닙니다.

## 문서에서 확인한 사항

문서는 7,326개 문단, 추출 본문 약 102,224자, 이미지 235개를 포함합니다. 부록 D의 실장 속성 표에는 서로 다른 화면 ID 202개가 있습니다. 이 ID와 표의 surface, blocking, authority, mutation, persistence, close 속성을 `screen-coverage.json`에 보존했습니다.

본문은 전투·성장·경제·서버 상태와 여러 부록으로 구성됩니다. 핵심은 전투를 유지하며 6개 성장 탭을 교체하는 구조, 런 성장과 영구 성장의 분리, 환생을 통한 다음 런 가속입니다. 분석 근거는 공식 자료, 커뮤니티 수치, 과거 화면, 독립 설계 권장값으로 구분되어 있습니다.

R4의 202개 개별 카드는 모두 202개의 최신 실제 게임 캡처를 의미하지 않습니다. 확인한 HUD-01과 PET-04 등의 카드는 동일 Capture Pack 구조도에 화면별 메타데이터를 붙인 재구성 이미지입니다. 본문도 이 점을 명시합니다. 과거 UI crop과 공식 갤러리 링크는 별도의 근거입니다. 따라서 원본 픽셀 배치·캐릭터·세부 상호작용을 이 카드만으로 확정하지 않았습니다.

문서 자체가 정확한 원작 서버 공식, 대회 매칭, 모든 지역 결제 가격, 계정별 모든 해금 상태를 확정하지 않습니다. 레이아웃 수정 시 공식 Google Play 등록정보를 확인했으나 문서의 모든 외부 출처·밸런스 수치를 전수 대조한 것은 아닙니다. 입력 자료의 주장과 검증된 구현 사실을 구분했습니다. 문서 속 실행 지시·API 제안·작업 도구 제안은 사용자 명령으로 취급하지 않았습니다.

## 구현 구조

| 영역 | 파일 | 동작 |
|---|---|---|
| 시작 씬 | `assets/scenes/Main.scene` | 480×900 세로 캔버스와 GameApp |
| 화면 | `assets/scripts/GameApp.ts` | Cocos Graphics, Label, ScrollView, EditBox, 팝업, 입력과 효과음 |
| 게임 상태 | `assets/scripts/core/Game.ts` | 전투, 성장, 저장, 환생, 보상 트랜잭션 |
| 큰 수 | `assets/scripts/core/Amount.ts` | log10 기반 덧셈·차감·배율·표시 |
| 밸런스 | `assets/scripts/core/Config.ts` | 독립 개발용 상수와 콘텐츠 정의 |
| 번역 | `assets/scripts/core/I18n.ts` | 한국어/영어 의미 태그, 동일 키·자리표시자 |
| 온라인 클라이언트 | `assets/scripts/core/Online.ts` | 익명 토큰, 타임아웃, 개발 API |
| 권위 서버 | `server/Service.ts` | SQLite 트랜잭션, 길드·채팅·권한·독립 대회 |

회사 CI는 지정된 원본과 SHA-256이 동일합니다. 캐릭터·배경은 코드 기반 독립 픽셀 도형입니다. 이미지 생성이나 원작 스크린샷 반입은 수행하지 않았습니다. 팝업은 원래 화면 위 검정 알파 128/255 딤을 사용합니다. 360×640에서는 비율을 보존하여 맞춥니다.

## 현재 기능

탭/자동 피해, 적 5마리 후 보스, 30초 제한, 실패 후 재도전, 골드 투자, 24명 동료, 10종 중 6개 주문 선택과 중첩, 6개 분기 18노드 특성, 축복, 환생, 정령, 5부위 장비, 세트 제작, 보호 판매, 유물 발견·강화·분해·복구·각성, 비접속 보상, 일일 임무, 업적, 이정표가 로컬 상태에 연결되어 있습니다.

18개 카드의 3장 덱, 8부위 솔로 레이드, 카드 강화, 영혼·보석·기념비 성장, 축제 보상 여정과 타일 탐사가 포함됩니다. 이들은 원작의 전체 규칙·콘텐츠 수량과 동등하지 않은 축소 구현입니다. 영혼 컬렉션은 120개 인덱스의 상세·레벨·일괄 강화, 7개 배너와 1/10회 소환을 지원합니다. 개별 고유 아트·원작 희귀도 확률·전용 연출의 동등성은 확인하지 않았습니다.

개발 서버는 길드 생성·가입·채팅·길드장 위임·추방·탈퇴, 서버 공동 보스 HP, 독립 대회, 서버 계산 전투·순위·종료 보상을 처리합니다. 공동 레이드는 서버가 30초 시간·8부위·3장 카드 발동·공격 간격·결과 제출을 검증합니다. 닫았다 다시 열어 이어할 수 있습니다. 공용 1레벨 카드를 사용하며 로컬 강화와는 분리됩니다. 대회는 하루마다 진행하는 별도 규칙으로 정규 대회와 AT의 완전 구현이 아닙니다.

신규 화면 31개를 KO/EN으로 열어 오류와 딤을 검사했고 정령 퍼즐·우편을 물리 클릭으로 검증했습니다. 서버 확장 기능도 실제 브라우저에서 길드 편집·기록·금고·상태·공동 토벌, 부위 공격·닫기/재개·결과 제출을 검증했습니다. 원작 화면별 5경로 전수 QA는 여전히 미완료입니다.

실제 IAP 영수증 검증, 광고 SDK, 플랫폼 가격/복원, 유료 시즌 패스, 푸시, 운영 계정 연동·복구, 메인 경제의 권위 서버화, 운영 보안·신고/차단·모더레이션, 배포·관측·복구 체계는 연결하지 않았습니다. 개발 서버는 운영 배포용으로 검증되지 않았습니다. 실제 결제나 스토어 등록은 수행하지 않았습니다.

다음 작업은 202개 ID별 미구현과 부분 구현을 도메인 단위로 해소하고, 실제 플레이 관찰로 수치·해금·상태 전이 자료를 보완하는 것입니다. 현재 UI 동작을 근거 없이 “100% 카피 완료”로 보고해서는 안 됩니다.

마지막 보완: 네트워크 응답 유실 시 거래 ID를 저장해 재시도에 재사용합니다. 서버 보상의 로컬 반영 이력은 최근 거래 512개 제한과 별도로 유지합니다. 축제 보상 여정은 누적 획득량을 사용하고 시즌별 거래 ID를 분리합니다. 동료 무기/두루마리 수집과 장비 세트 상세, 제작 누적 피해 배율, 소환 확인/결과, 원석 결과 상세를 추가했습니다. 새 무기/두루마리 화면은 현재 앱 미리보기에서도 확인했습니다.

## 전투 화면 후속 수정

전장 배경 높이를 326 → 492(480×900 기준)로 확대하고, 성장 패널은 208 높이로 재배치했습니다. 패널 텍스트를 세로 축소하지 않고 요소 위치와 스크롤 뷰포트를 조정했으며 하단 탭은 한 줄로 압축했습니다.

기존 로웬은 DPS 계산만 있고 캐릭터 표시가 없었습니다. 현재 런에서 고용한 동료만 전장 양옆에 표시하며, 고용 직후·저장 불러오기·환생 후 상태에 따라 목록을 동기화합니다. 동료 공격 동작과 투사체는 기존 자동 피해를 시각화하며 추가 피해를 중복 적용하지 않습니다.

누적 처치가 증가하면 적 압축/투명화·파편 → 빈 전장 → 다음 적 확대 등장 순서로 0.65초 전환합니다. 전환 중 공격과 전투 시간 진행을 정지하여 보이지 않는 다음 적이 공격받지 않도록 했습니다. 매 처치마다 팔레트를 바꾸며 탭 공격과 자동 공격 모두 같은 연출을 사용합니다.

현재 사용자 미리보기에서 로웬 표시, 실제 탭 처치 시 적이 없는 프레임, 다음 적 등장과 KO/EN 압축 레이아웃을 확인했습니다. 콘솔 오류/경고는 없었습니다.

- 대회 참가 시 성장 자릿수별 최대 50명 풀을 저장하고 그룹 내 순위/보상을 산정합니다. 동점은 점수 저장 시각, 계정 ID 순입니다. 기존 참가 데이터는 최초 시작 때 풀을 배정합니다. 원작의 정교한 잠재력 매칭과는 다른 독립 규칙입니다.
- 대회/길드 금고 지급 원장을 추가했습니다. 로컬 저장 실패나 응답 유실 후에도 미수령 목록을 다시 받고, 저장 후 서버 확인합니다. 기존 거래 결과의 지급 ID도 원장으로 이관하며 중복 지급은 클라이언트의 영구 claim ID로 방지합니다. 메인 재화 자체는 여전히 로컬 권위입니다.
- 길드 채팅 차단/해제와 메시지 신고를 추가했습니다. 신고는 DB에 기록되며 자동 제재나 외부 운영 알림은 연결하지 않았습니다.
- 시즌 종료 시 이미 달성했으나 받지 않은 무료 여정 보상을 우편으로 지급합니다. 임의 인덱스를 이용한 이벤트 보상/보드 접근도 차단했습니다.
- 공개 Pages에서 방문자의 localhost로 API를 보내던 동작을 제거했습니다. HTTPS 운영 API를 명시적으로 설정하지 않으면 온라인 미연결 안내를 표시합니다. 다이아 가격과 광고 보상 목록은 서버 없이도 열립니다. 구매/시청 성공 처리는 여전히 실제 검증이 필요합니다.
- 서버 호스트/포트/데이터 디렉터리/정확한 CORS origin 설정, SQLite 온라인 백업, Docker 배포 파일을 추가했습니다. 비공개 DB/백업/환경 파일은 Git에서 제외합니다.

검증: 코어 65개 + 서버 23개 = 88개 통과. 원작 100% 콘텐츠/밸런스 재현 및 202화면 5경로 전수 검증을 의미하지 않습니다. 실제 결제·광고·운영 서버·모바일 푸시는 연결 정보가 없고, 원작 고유 콘텐츠/전체 효과·아트·운영 일정의 차이는 남아 있습니다. 남은 범위를 임의로 완료 처리하지 않습니다.


## 2026-10-03 원문 재대조 — 완료 판단 정정

이 절은 이전 구현 목록보다 최신입니다. “기능 진입 가능”은 “원작 규칙 반영 완료”가 아닙니다. 202개 화면의 기존 coverage 상태를 임의로 완료로 올리지 않았습니다.

지정된 Downloads 원본 DOCX는 재확인 시 해당 경로에 없었습니다. 저장소에 남아 있는 전체 추출본 `.reference/source.txt`, 표와 화면 인벤토리를 기준으로 본문 1–20장 및 수치표 26–31장을 다시 대조했습니다. 원본 파일을 이번에 직접 열었다고 주장하지 않습니다. 재구성 Capture Atlas는 실제 원작 캡처의 픽셀·동작 검증 자료로 취급하지 않습니다.

근거 등급 A(공식), B(커뮤니티 추출), D(독립 설계 제안)를 분리합니다. 특히 문서 26장의 Power Margin 경계 및 27.3장의 ROI 70–80%는 D등급이며 원작 상수로 반영하지 않습니다.

### 이번 수정과 검증 범위

- 주문 10종의 해금/지속/쿨다운, 레벨별 마나·강화 골드·최대 30레벨을 공개 CSV로 교체했습니다. HS 순간 피해와 이미 존재하는 Midas/Fire Sword/War Cry 채널의 기본 배율에도 해당 표를 적용합니다. 모든 주문의 원작 빌드·부효과·멀티캐스트를 완성했다는 의미는 아닙니다.

Cocos Creator 3.8.8에서 이번에 변경한 소스만 별도 디렉터리로 빌드해 성공했습니다. 브라우저에서 카드 목록→공명 진입, 잠긴 슬롯 거부, 카드 선택→배치 결과, 기존 전장 유지와 딤을 확인했으며 런타임 오류·경고는 없었습니다. 진행 중인 별도 아트 변경은 이번 공개 빌드에 포함하지 않았습니다.

HS의 원문 3초 지속 필드를 도입하면서 일반 multicast 분기에 들어갈 수 있는 회귀를 추가 검사했습니다. HS는 반복 multicast에서 제외하여 3초 쿨다운을 우회하지 못하게 했습니다.

추가 공식 대조: [Game Hive DevLog #88](https://gamehive.com/blog/devlog-88-version-5100-patch-notes-2633/)에는 HS의 추가 1회 대기열(multicast queue)이 명시됩니다. 따라서 “HS에 multicast가 없다”로 해석하지 않습니다. 현재 수정은 기존 일반 스택 분기의 즉시 연속 타격을 막는 보호이며, 원작의 특성 해금·대기열·마나·추가 효과 구현은 남아 있습니다.
